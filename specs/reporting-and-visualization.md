# 报表产品与财务图表设计系统 v0.1

2026-10-30。状态：需求和设计合同，图表尚未全部实现。首页月度实际收支已另行交付；本规范不改变账本、采用预算、科目或 AI 权限。

## 1. 报表要回答的问题

报表页从“并列三张表”升级为一个可探索的财务工作台。首页保留当月收入、消费支出、收支结余、现金净流入四项，点金额进入同口径明细；报表负责解释构成、变化、预算差异与账户资金。三大表作为可核对的数据视图继续保留。

| 工作区 | 用户问题 | 默认呈现 | 进一步展开 |
|---|---|---|---|
| 总览 | 这段时间赚、花、留下多少，变化来自哪里？ | 四项实际数、收入/费用趋势、收支构成桑基图 | 收支差异瀑布、报销口径桥接、三大表 |
| 消费 | 花在哪里，结构怎么变，哪些值得检查？ | 科目排行、期间构成百分比堆积、大额列表 | 商户排行、日历热力、金额分布、事件/生活用途 |
| 预算 | 已知占用多少，哪里超过安排，目标还差多少？ | 预算/实际横向比较、月度预实、目标桥接 | 明确用途、固定待付/分期、节省情景 |
| 现金与账户 | 钱在哪，现金怎么流，银行余额能否对上？ | 实际现金收付、账户余额/负债表、覆盖与差异 | 现金路径、余额趋势、债务到期、未来现金 |

投资留在“现金与账户”的后续子视图，R09 达标后再开放持仓和收益图。AI 解释是当前结果的解释面板，仍由 Codex 读取冻结结果；不另起一个数字口径不同的聊天报表。

每个工作区默认最多显示三张主图，下面配可下钻的表。分布、日历和进一步诊断按需展开，不把全部图谱同时铺满页面。无数据的能力不显示可用入口。

## 2. 页面布局

```text
报表    总览 / 消费 / 预算 / 现金与账户
期间 [月度 ▾] [2026-08] [前一期] [后一期]
范围 [全部纳入账户 ▾]  口径 [账面收支 ▾]  比较 [上期 ▾]
当前筛选 · 数据修订 · 覆盖状态                       [重置] [保存快照]

收入                 消费支出              收支结余             现金净流入
数值、较可比期间差异；数据不足时保留已知值与缺口，不伪造完整性

主图 A：当期收支/趋势（通栏）         [图形 / 数据表 / 解释]
主图 B：构成/桑基    | 主图 C：重点排行/预算差异
组成明细（可筛选、分页，合计使用全量）

选中标记 → 选中摘要与明确操作 → 明细/商户/筛选/比较
口径依据、报销调整、覆盖缺口和原始表作为可展开区域
```

手机使用单列、四个紧凑工作区入口；期间与口径常显，次级筛选折叠。图表标题和金额可读，点击可选中，无需悬停。选择后的操作在底部 Sheet 中完成。复杂桑基在手机默认展示守恒的两侧汇总和连接，点击“展开流向”再看完整图，不把桌面宽图缩到无法读字。三表精确核对允许表格区域横向滚动，整页不横向溢出。

## 3. 时间、粒度、比较

### 3.1 全局期间

- 从首页进入：沿用首页选中月份。
- 可切换月度、季度、年度、近12月、自定义起止日。URL 保存期间、口径、账户、维度和下钻路径；刷新、后退保留。
- 历史完整月按自然边界；当前月/季度/年度标“截至某日”。未来月份没有实际，不能填0；只有计划的2027年可以画计划，实际位置留空。
- 年度视图同时给“已记录累计”和明确分母的月均。资料缺失月不当0，完整且无交易才显示0。
- 当前后端 `/reports?month=` 和 `/analysis` 的自然月窗口不能直接冒充自定义日级能力。V01先统一月份区间，日级筛选在V02完成后开放；不展示无效控件。

### 3.2 汇总粒度独立于期间

建议自动粒度：1–45日按日，46–120日按周，121–730日按月，更长按季度。用户可选日/周/月/季度，系统注明部分首尾分桶。周从周一开始，跨年用完整日期标识，按 Asia/Shanghai 解释日期；不因为切换粒度改变期间起止或月份分母。日级尚未实现时只提供月/季度。

### 3.3 比较

上期、去年同期、自选基准。只比较相同指标定义、币种、范围及可比覆盖；完整8月与缺半个月的7月不能直接给“环比增长”。当前月默认与上月同截至日比较，并保留两边覆盖警示。缺2025年不画2026同比；基数为0显示绝对差异，增长率为不适用，不能显示无穷或100%。年度已记录与上年全年不能直接比较。

## 4. 口径契约

1. **账面收支**：收入 I、净费用 E、结余 I−E，消费按确认日，报销按到账日，退款按退款发生日抵费用。还款、本人互转、投资本金划拨不再次计消费。
2. **报销调整分析**：同窗 I/E/R/m，I*=I−R，E*=E−R；调整以独立桥接项呈现，不摊入餐饮、酒店等科目，也不制造真实退款。家庭赞助不进入R。未来净工资计划不再抵R。类别占比仍来自账面费用，不能把未分配的R硬分给类别。
3. **生活预算**：采用预算行执行规则，消费占用与有证据的付款占用互斥；计划、已知占用、未知剩余、预测分列。未采用草稿仅在预算草案比较中显示。
4. **现金**：按实际收付日，计一次现金事实。已确认本人现金互转从合并现金流中剔除；未解释现金变动独列，不猜成费用。信用消费影响负债，不在刷卡日伪造银行付款。
5. **余额**：截至明确日期的存量，不能把各月余额相加。期初未知不画精确净额；外部观察、按流水推演与已解释账面分别显示。不同日期观察不凑总资产。

口径切换会更新所有兼容结果；不兼容图给出替代表达。禁止在同图中把消费金额和还款金额相加，或把预算留存当作实际储蓄到账。

不将漏斗、雷达、3D、词云列为默认财务图。消费排行需要累计占比时采用共享X轴上下两图，默认不用双Y轴帕累托。未经验证的异常检测不使用“异常消费”标题；“冲动/不合理”需要用户语境与目标，不从金额或商户名直接判定。

## 6. 两张重点图的金融语义

### 6.1 收支构成桑基

左侧：劳动收入、家庭赞助、报销到账、其他已确认收入，以及独立的“退款及费用抵减”。中心为“本期已记录收支”。右侧为毛费用科目，以及“收支结余”。没有付款/订单强关系时不画“某来源→某商户”的假资金链。

令 G 为正费用毛额，F 为负费用抵减的绝对值，E=G−F，S=I−E。所有链路非负：

```text
收入来源 I + 退款/费用抵减 F + 统计缺口 max(−S,0)
                         ↓
                 本期已记录收支
                         ↓
             正费用 G + 收支结余 max(S,0)
```

例（合成值）：收入1000、毛费用1200、退款100，则净费用1100、结余−100；左侧收入1000+退款100+“收支缺口100”，右侧毛费用1200。缺口是算出的收支差额，不代表已证实取存款或新增借款。若未来出现负收入项目，应先纳入明确的收入冲减桥接，否则退为带正负的表/瀑布，不能取绝对值。

该图可以在 partial 数据下展示**已记录范围**的守恒，但不能标“完整资金流”。守恒只校验计算，不证明资料齐全。范围、来源、分和交易引用均由后端生成，不由模型或前端拼平。手机/高节点数优先展示收入合计→已记录收支→费用合计/结余；进一步在选中的费用节点展开科目。

### 6.2 百分比堆积

- 默认维度为月份×费用科目，展示“净费用结构”，同一科目在所有月份保持同一身份和顺序。tooltip同时给金额、占比与分母。
- 仅当每个构成项非负且总额>0时画净费用100%堆积。某类净费用为负时，明确切换“毛费用构成”，退款另列；原始净费用总额依然可核对，不能截掉退款或把净额取绝对值。
- 总额为0不算百分比；已确认完整零月显示“0元/无构成”，缺月显示“资料缺失”，两者不画成100%空柱。
- 常规最多5个可见系列。超过上限使用显式“Top4＋其余N项”的**展示汇总**；存在未分类5016时改为“Top3＋未分类＋其余N项”，仍不超过5项。列出余项成员并可展开为排行/小倍数。这是本应用对EIX“不得静默折叠”的受控扩展，不新增“其他支出”科目，不改变任何原分类。Top集合按整个窗口确定，不能每月换Top。未分类5016必须另标，不能藏入余项。
- 选择或淡化图例不重算分母。只有明确“筛选整份报告”才更新查询并显示新分母范围。金额与百分比模式切换保留同一结果、同一系列顺序。
- 服务以精确金额和分子/分母给比例；显示取1位小数时采用统一余数分配，使有数据月份显示合计100.0%，提示精度。绘制近似坐标不能反过来决定金额。

## 7. 放大、缩小和下钻

三件事独立保存，不用一个含糊的zoom开关。

| 操作 | 改什么 | 默认行为/返回 |
|---|---|---|
| 放大/缩小时间范围 | 整份报告的起止日 | 年→季度→月→选中周/日；选择时间桶后点“查看这段时间”。“返回上级期间”恢复完整前一查询 |
| 切换汇总粒度 | 同期间如何分桶 | 日/周/月/季度；总额不变，边界部分桶注明，不自动改变账户或类别 |
| 维度下钻 | 按什么维度解释同一金额 | 科目→明确商户/原始摘要组→交易→原始行/原件/修改历史；面包屑和返回恢复筛选、滚动及图例选择 |
| 展开图形 | 当前图的阅读尺寸 | 大图/Sheet，不改变期间、分母、合计或统计粒度 |

鼠标拖选或ECharts dataZoom只能先局部查看，显示“局部查看，汇总仍为原范围”；点“应用期间”才更新全局。手机默认用明确期间按钮，不劫持页面滚动，也不要求捏合、双击或悬停才能完成核心操作。点击标记先选中，给“查看组成明细 / 按商户展开 / 筛选整份报告 / 比较”操作，不能单击就悄悄改整页。

筛选跨图联动采用明确命令，不做任意图表相互刷选。局部强调保持分母；全局筛选统一重取同一结果。返回上级恢复上下文；“重置全部”回到入口期间和默认口径。

## 8. 从既有Design System借什么、补什么

来源：[EIX图表样例](http://8.160.176.104/eix/design-system/collaborative-visualization/samples/index.html)，本机对应`collaborative-visualization`的候选扩展v0.1.0。已经核查README、Design JSON、ChartSpec schema、React ChartBlock、ECharts适配器和validator。它是参考实现，不能按22种图谱=22种已完备生产组件理解。

| 原有能力 | 复用方式 | 财务扩展/修正 |
|---|---|---|
| ChartBlock、resultRef、图/表/解释 | 保留同源结果契约，外壳接现有Finance的@tuja/ui | 标题优先用户问题；金额、截图、依据和下钻共享修订。解释数字引用指标，不独立生成 |
| task→router→validator→renderer | 保留确定性选型、停止条件与降级 | 增加basis、退款策略、预算采用版、区间覆盖、余额定义、分母、金额精度等门槛 |
| 系列色/状态色隔离、稳定seriesId | 复用身份注册表、常规5系列上限、浅深主题 | 应用按钮继续墨黑；图表颜色不继承按钮accent。科目/指标ID稳定，不按排序换色；高基数用强调/小倍数，不循环颜色 |
| Actual/Plan/Forecast线型 | 实线/虚线/点线，计划与事实分开 | 当前没有可验证预测时不显示Forecast；未知值与0分开 |
| ECharts适配器 | 借其受控option和模块化引擎策略 | 当前100-percent与普通stack共用stackedOption，缺归一化；必须补100%计算、固定0–100%轴、分母与负值校验。禁止直接接该分支冒充百分比图 |
| Sankey validator | 保留节点流入流出守恒、非负检查 | 在分整数上验证；再加业务口径与双端去重。原参考全图>7节点停止；财务桌面可经密度验收扩到12节点/18边，手机≤7，否则显式聚合/分层 |
| React参考ChartBlock | 借状态与视图分离、ResizeObserver/清理模式 | 不复制MBCorpo字体、企业壳或云端权限；沿用本应用中文字体和主题。引擎实例不随普通重绘销毁，缩放/选择可恢复 |

补充财务图语法：跨期退款发生视图vs原消费归因视图、报销总额桥接、收入/费用/本金分离、期初未知、余额存量不可累加、预实三种basis、隐私版仅支出导出。日期/范围/类别的层级探索不由图库默认行为替产品定义。

## 9. 数据、组件与版本

建议服务新增统一只读查询`POST /report-results/query`，返回一次SQLite读快照内的`FinanceReportResult`。保留旧月度接口兼容；先复用已验财务函数，再补日级/多月投影。不可把浏览器分页的50笔当全量算图。

```text
FinanceReportResult
  result_id + query + scope_hash
  dependencies: financial/evidence/coverage/observation/dimension/classification-rule/journal-rule/adopted-budget/definition versions
  metrics: 精确分字符串
  series: 桶、类别ID、amount_minor、分子/分母、quality、reference_set_id
  tables: 同源事实/比较/桥接
  quality: complete / partial / unavailable + 具名原因
  charts: 由注册表选出的FinanceChartSpec，不能任意ECharts option
```

FinanceChartSpec组合EIX ChartSpec与`finance`扩展，见[语义schema](../design/finance-visualization/finance-context.schema.json)。前后端都校验，业务真值以服务为准。金额计算用整数，显示比例由精确分子/分母计算。绘图坐标可近似，但不写回金额；超过JS安全整数范围且无经验证缩放时退表。

图表组→稳定引用集合→明细：后端返回`reference_set_id`，包含交易ID、版本、角色及金额贡献。明细分页按该引用集合及同一修订取数，支持正负贡献分别核对。统计缺口/结余等派生节点标`derived`，引用确定性计算及其I/E来源集合；点击展示桥接依据，不伪造一笔缺口交易。新接口不能把任意SQL或计算表达式暴露给浏览器/模型。

维度/事件非互斥标签不能直接堆叠求和。用途未关联独列；旅行/大件/日常事件尚未实现的分区显示待归属，不根据餐饮/交通科目猜成日常。账户、商品证据、规则或采用预算变化使结果过期；旧快照冻结值不改。“按当前口径刷新”保留参数，整批切换结果，禁止新旧图混放。

前端模块：`FinanceReportFilters`、`FinanceChartBlock`、`FinanceChartRenderer`、`FinanceSeriesRegistry`、`ChartSelectionSheet`、`ReportDrillBreadcrumb`。继续复用现有Finance外壳和控件；引擎建议按需加载ECharts的SVG renderer，首屏只加载当前视图图种；不是新增通用BI编辑器。

## 10. 展示、可访问性、隐私

- 普通按钮墨黑，可保留已有深绿/藏蓝偏好；选择态、请求状态和数据含义分开。净额正负带符号及文字，不能只用红绿。
- 沿用现有中文字体和数值排版，不引入样例的企业专用字体或日文字形包。深浅主题、320/390/768/1440px分别检查标签、轴、图例与Sheet。
- 无障碍摘要和同源数据表必备；键盘能选中与下钻，44px触摸目标，减少动效偏好有效，图形不是唯一信息来源。
- 金额条形从0起；净费用可在0两侧，不能截断负值；无约束双轴禁用。饼/环只用于很少类别的补充，不能替代可比较的条图。
- 分享版“仅支出”在生成的数据对象中移除收入、结余、余额、账户识别、工资引用与隐藏元数据；不是CSS隐藏KPI。导出来自冻结结果，跟页面同版本；R08实现前不声称已可分享。
- 固定图表标题用问题或有证据事实，AI建议和假设另标。不把某商户、金额大小或低置信判断写成已证实的消费原因。

验收必须覆盖以下反例，新增到自动化与浏览器脚本后才能标交付：

1. 信用消费100、银行还款100、信用端还款100：消费图100，合并现金仅实际付款100，桑基不画300消费。
2. 收入1000、正费用1200、退款100：净费用1100、结余−100；桑基非负且守恒，缺口不伪装借款；负构成不被强塞100%图。
3. 同窗I=1100、E=600、R=100，两月平滑：I*=1000、E*=500，结余保持500；餐饮/酒店科目不被任意摊减。净工资计划不再抵R。
4. 完整零月、缺月、未来月：0、未知、计划分别呈现；同比无可比窗口不报增长率；0基数不报无穷。
5. 占比切换总额不变；所有可见部分+显式余项=同源总额；未分类始终可识别；图例强调不改分母。
6. 时间范围、汇总粒度和维度下钻独立；图/表/导出同修订；后退、刷新、保存快照及过期后刷新保留参数。
7. 余额期初未知但有两次观察：只能比较区间变动，不能生成精确净额曲线；不同日观察不相加。
8. 退款跨月、跨年、未关联、超额分别处理；未证实的跨年预算释放/融资路径不能靠绘图猜配。
9. 100条以上商户、超长中文、超大整数、负值、少样本、全部缺数、主题切换、320px、键盘操作与大数据标签密度均可降级且无横向整页溢出。
10. 仅支出分享内部数据无收入、结余、余额与其可反推字段；不以截图肉眼看不到作为隐私验收。
