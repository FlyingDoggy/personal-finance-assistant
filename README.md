# 个人财务管理助手

当前开发版本：`0.5.0-dev.3`；已发布的源码预发布标签为 `v0.5.0-alpha.1`。源码包含应用、规格、技术方案、锁定依赖和合成测试；不含个人账本、银行原件、配置、预算成品或访问凭据。

本地优先的个人资金与交易管理应用。轻量 ETL 汇集流水，SQLite 保存账本、证据和修改历史；FastAPI 提供正式计算与受控写入；React 展示三表、预算、原始明细、凭证与疑点。Codex 通过独立 MCP 执行受限分类，模型不直接写数据库。

需求规格 v0.5 已作为开发基线，首批实现覆盖 R00 完整备份、R01 首个原生导入与账务边界修复、R02 持久分类任务和 MCP 协议。全量 v0.5 尚未完成：真实模型写入门槛、复杂关系/对账、事件复盘与 AI 解释、未来资金安排、投资、分享导出等继续按切片实施。具体证据和限制见[开发与验收记录](plans/implementation-status.md)，技术分工见[技术方案](plans/technical-design-v0.5.md)。

新增入口：**更多 → 导入批次 / AI 待办**；**设置 → 数据 → 完整备份与恢复 / 覆盖范围**。默认墨黑按钮，偏好保留深绿与藏蓝。schema 5 采用增量建表，既有交易、历史、原件和已采用 2027 预算保持不变。

## 第三批开发：月度汇总与账本维护

首页先展示当月收入、净消费、收支结余和现金净流入，未设置预算的历史月也可查看；点击金额下钻同口径交易。消费扣退款，还款不重复计费用，现金按实际收付独立统计。

“交易 → 手工补录”先检查统计影响与同账户同日同额候选；“更多 → 余额核对”可追加银行日终观察、设置有依据的日初起点、查看差额和补录遗漏。观察不自动变期初，也不自动补差入账；更正保留旧值与理由。交易详情可下载校验过的原件，手工记录以第1版人工依据留痕。支持同账户历史消费与新退款的累计金额校验、科目传播和成组撤销。

schema 4→5增量迁移和完整恢复已验，采用预算与原始交易保持。边界：其余来源格式、跨来源重复合并/拆分、多对多/跨日关系、跨年预算释放仍待实现。详见[账本维护技术合同](plans/technical-design-r04-ledger-maintenance.md)。

报表图表另有[产品与交互规格](specs/reporting-and-visualization.md)和[财务图表设计系统](design/finance-visualization/README.md)：规划四个工作区、16类图、时间/粒度/维度探索，明确桑基与百分比堆积的退款、分母及去重约束。此为设计合同，图表目录不代表已全部上线。

## 第二批开发：预算、规则与分析

“预算”中的修订先保存草稿，核对差异并明确采用后才影响首页和正式预算查询。“交易”支持勾选正费用消费并批量确认科目或预算关联，保留修改历史。

“更多 → 分类规则”可保存规则草稿、预览影响、启用和停用。启用用于以后适用的新流水；旧记录另行预览并确认应用，人工分类优先，同级冲突转待核。

“报表 → 消费与报销分析”或“更多”进入同窗分析，选择月份、实际到账调整/累计平滑、大额门槛和估计模式。主账保留总额，消费标准化两侧减同期报销；生活来源另行声明是否包含报销，不能再次抵减已排除报销的计划工资。分析快照保留保存时结果，依据变化后提示过期。

本轮 schema 4 增量登记既有采用预算，保留历史交易和金额。详见[第二批技术方案](plans/technical-design-r03-r05.md)。MCP 权限隔离与完整语义评测仍未完成，真实账本 AI 写入继续关闭。

## v0.5 首批流程

上传招商信用卡文本 PDF、标准 CSV 或支付宝商品明细 XML/XLS → 查看解析预览 → 确认处理 → 查看分开的来源行、业务和疑点计数。关闭窗口后可在导入批次继续；未支持文件不会作为成功入账。支付宝商品明细只补商品证据，不新增资金支出；不明确的分期本息保持待核。

未分类但已确认的消费先计入已知支出。准备 AI 任务后，将生成的指令交给已连接财务 MCP 的 Codex；任务领取、来源证据、分类提交和回执均持久保存。上传本身不会启动模型。MCP 配置与实测边界见[连接说明](specs/mcp-connection.md)；生产未配置机器令牌时明确显示未配置，不宣称后台 AI 已开启。

覆盖声明按账户、月份、消费/付款口径分别维护。资料未齐或仍有未知性质时显示已知金额，不把缺失当零，不以某个月有数据推断全年完整。银行转出和卡端还款分别保留本端证据，不凭局部同号自动配对；新增信用还款不能随意绑定付款预算而重复占用。

## 启动独立应用

使用 Python 3.12+ 与 Node.js 22.12+。当前环境以 Python 3.14 和 Node.js 24 验证，依赖按锁文件安装：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
npm --prefix web ci
npm --prefix web run build
.venv/bin/python scripts/run_app.py
```

打开 [本机生活账本](http://127.0.0.1:8765)。服务默认只监听本机，新库位于 `data/app/finance.sqlite3`，原件位于 `data/app/originals/`。已有 `data/finance_processed.sqlite3` 和预算成果继续作为迁移基线，新应用不会自动导入或覆盖它们。终端 Ctrl+C 停止服务，重新运行同一命令可恢复已保存数据。

历史数据迁移需要显式执行：`scripts/build_migration_bundle.py` 只读导出既有解释及证据，`scripts/stage_legacy_migration.py` 写入独立空目录，`scripts/reconcile_migrated_ledger.py` 对照从最终 Excel 独立提取的基线。通过后停服务、保留旧应用目录并切换新库；不能直接往在线库强行导入。每次来源变化须重新生成 Excel 基线及迁移包，哈希不匹配会停止。当前一次迁移的私密输入与完整检查保存在 `work/migration-20261029/`，不提交仓库。

迁入交易的列表金额沿用原始银行符号，详情另列实际收入、费用和现金影响；不使用标准 CSV 的符号规则再次解释。无日期记录和原统计范围外资料可在交易页选择“全部期间”查看。历史余额快照保留各自证据日期，不能倒推期初或合成同日总余额。预算使用独立月份选择，不改变正在查看的历史交易月份。

先添加账户；起始余额未知可留空。再从导入窗口选择账单并预览，标准 CSV 可下载模板。模板金额是人民币账户净变动：现金减少为负、信用负债增加也为负；不能把原银行金额不经方向转换直接粘贴。来源身份使用命名空间、账户和来源编号；不同账户同号不会直接合并。没有稳定交易号的原生文件使用来源位置标识，同日同额仅提示候选。已迁移原件可关联原业务，不重建历史。

年度预算保存生成草稿版本；显式采用后成为本年当前计划。普通消费可在详情中关联预算项目。已知普通消费即使未分配预算项目，也计入已知总占用与日常占用；资料覆盖不足时不显示精确可用余额。当前仅保存计划的分期不会自动产生还款或真实负债。完整预算计量规则见主规格第 12 节。

开发验收：

```sh
.venv/bin/python -m pytest tests_app -q
python3 -m unittest discover -s tests -q
npm --prefix web run build
```

浏览器验收另需安装 `requirements-dev.lock` 和 `.venv/bin/python -m playwright install chromium`，再执行 `.venv/bin/python tests_browser/smoke.py`。脚本自动启动临时服务与隔离的合成测试库，结束后清理服务和数据库，不向个人应用库写演示资料。桌面及 390px 手机视口截图保存在 `work/acceptance/`。

前端直接复制并使用上游 `@tuja/ui` 源码、StyleX 构建链，以及 Finance 的布局、交易行和统计展示组件；以本地 API 适配财务业务。完整来源、改动及 MIT 许可见 [第三方声明](THIRD_PARTY_NOTICES.md)、[组件库记录](web/vendor/UPSTREAM.md)及 [Finance 展示组件记录](web/src/upstream/UPSTREAM.md)。

一期只维护资金账户、投资、公积金、必要往来及债务，不要求房产、汽车或日常耐用品盘点。普通耐用品购买时计消费；支持直接编辑并保留修改历史，无强制冲销、月结、折旧或预付摊销。已确认消费可先记为未分类支出，不漏出总消费和预算；性质不明的收付保留待解释状态。

## 可选历史加工工具（独立应用无需使用）

1. `scripts/inspect_sources.py` 以只读方式建立原始数据库与旧测算工作簿的本机清单；旧测算不是实际发生额。
2. `python3 scripts/process_finance.py --config data/processing_config.json` 产生独立的 `data/finance_processed.sqlite3`。保留原始证据表，新增当前交易解释、关联、部分已确定分录、现金事实、科目和校验清单。
   v0.3.1 会读取已归档支付宝商品说明，按银行、付款卡、金额与日期双向唯一匹配补充分类证据；不另导入一遍消费。跨日匹配另需完整商户一致。商品证据、商户用途推定和用户规则分别留痕；退款跟随关联原单最终类别。
3. 历史报表生成曾使用个人定制脚本 `prepare_finance_workbook.py`，它包含一次性私人参数，留在本机而不随源码发布。新安装使用独立应用入口，不依赖这份脚本或已有 Excel。
4. `scripts/build_workbook.mjs` 是可选的 Codex 工作区导出工具，需要该工作区提供 `@oai/artifact-tool`。此依赖不在独立应用锁文件内；普通 checkout 不承诺可重建历史 Excel，也不需要运行此工具。

当前工作簿是可筛选的加工结果和可调整预算，不是数据库编辑界面。预算参数中的蓝色数字可改并重算；实际交易修改通过本机 `data/manual_overrides.json` 的交易 ID、修改字段和原因执行，然后重新生成。不要直接改原始来源。修订保存本次前后值；该旧脚本流程不代表当前独立应用；应用已经支持直接修改和历史，分期贷款完整流程仍待实现。不要把工作簿或manual_overrides的变更当作自动写回新应用库。

报销总额口径：工作垫付保留费用，到账计 4005 其他业务收入，家庭赞助使用独立事件类型。待报销事项只作备忘，不增加资产。预算按同一观察窗口汇总收入 I、费用 E 和已到账报销 R，用 R 同时抵减收入和费用，所有月均估计使用选定自然月数 m；汇总抵减行不改实际科目、日期或生成交易。窗口优先完整；用户明确选择包含部分末月的估计时，按选定自然月份数平滑并披露缺口，不按天数补足或声称资料完整。未来工资预算已不含报销，不再扣一次；家庭赞助不抵费用、不默认逐年重复。先抵报销再使用消费倍率。现金安排暂不含工作周转占款，不把平滑估计当作每月到账承诺。

历史重算检查点保存在本机 `data/checkpoints/`，各版 Excel 和预算结果保留。按用户明确选择，历史参考窗口为 2026 年 1—10 月：收入、费用及全部已到账报销均取同一窗口的已观察累计数，统一除以 10；10 月尚未完整，结果标为部分覆盖下的估计。10 月报销无需逐笔拆回此前月份，实际到账日期保持不变。待全年来源齐备后再更新草案，已采纳预算应保留版本。本次规格更新不重跑私人数据或修改现有预算金额。

检验：`python3 -m unittest discover -s tests -p 'test_*.py'` 使用合成数据，不读取个人财务资料。真实加工另校验原始文件哈希、来源行数、金额方向、分录平衡、内部转账净额、信用还款现金唯一性、总额报销政策及 SQLite 完整性。上述检查通过不代表交易用途或账户覆盖已经完整。

年度固定安排可在本机 `processing_config.json` 的 `annual_fixed_commitments` 保存稳定 ID、年度金额及付款月份。按付款月进入预算，不凭计划生成历史实际；识别到同一已确认年度费用时避免再在可变基数年化。

消费复核新增单笔门槛清单、退款净额、类别月均及未采用的额度方案。旅行专项通过已审核业务 ID 跨科目归集，可纳入提前预付与关联退款；行程内的日常订阅、还款和无关网购不因日期相同而计入。专项归集不新增费用；剔除历史旅行后的月均参照不代表下一年旅行预算为零，不能与额度方案重复计算节省。

个人定制的日常复核脚本 `prepare_daily_review.py` 留在本机，不随源码发布。可复用的 `spending_partition.py` 和 `prepare_trip_review.py` 已纳入仓库，按旅行、大件、固定、日常互斥归集，退款保留自身日期。历史假设中的旅行预算和独立大件预留不自动成为当前采用方案。最新年度参数、结果及展示政策保存在本机 `data/` 的相应配置与结果文件中；新应用迁移须逐项对照已采用版本，不能重新套用旧假设。尚未找到银行记录的消费只列待补备忘，未知人民币金额不填零、不猜汇率或造实际交易。

v0.4 将消费发生额、生活预算占用和现金收付明确分开：普通信用消费购买时占额度；明确按期付款的融资事项按履约额占额度；年度预留是计划，实际发生才占用。三种视图共用事实与版本，既不重复扣预算，也不把留存、可花额度和银行余额混为一谈。现有脚本不代表这些应用合同已全部实现。

旧加工脚本的账户标识默认从原记录读取；必要的末四位覆盖通过本机 `processing_config.json` 的 `account_last4_overrides` 配置，仓库不携带个人卡号。

## 完整备份与恢复

设置页创建 ZIP，包含一致性 SQLite 快照、引用原件、应用配置与校验清单。恢复先校验，再写入新目录，拒绝覆盖现有路径；任务旧租约失效，已提交结果和人工修改保留。机器密钥与 Codex 身份不进入备份。

也可运行 `.venv/bin/python scripts/restore_backup.py BACKUP.zip --destination NEW_DIRECTORY`，验证成功后停止服务，使用 `scripts/run_app.py --data-dir NEW_DIRECTORY` 启动该账本。界面恢复不会自动切换在线目录。本版备份包及展开总量限制为 512 MiB。
