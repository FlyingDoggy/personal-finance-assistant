# R03 / R05 第二批技术方案与交付范围

日期：2026-10-30，Asia/Shanghai。开发版本：0.5.0-dev.2。接续 v0.5.0-alpha.1，不改该发布标签。本轮目标是预算草稿/采用、规则治理与人工批量分类、确定性消费及报销预实分析；真实账本 AI 写入、事件分区和未来付款预测继续按各自切片验收。

## 1. 预算版本

保留不可变的 budget_versions.payload，schema 4 新增 budget_states 与 budget_events。既有最新计划增量登记为 adopted，过去版本为 superseded，原金额和来源不重算。新保存版本为 draft，明确采用后才变为 adopted；同一年仅有一个 adopted 的数据库唯一约束。

- POST /api/v1/budgets 现在只保存草稿；expected_version 检查最新保存版本，expected_adopted_version 检查编辑时采用版。旧客户端需要升级，不能再假定保存已采用。
- GET /api/v1/budgets?year=YYYY、首页、交易预算关联、凭证明细和采用预算查询只读取 adopted，另返回 latest_version。
- GET /api/v1/budget-versions?year=YYYY 展示草稿、当前与过去采用版，返回计划汇总和失去项目映射的影响。
- POST /api/v1/budget-versions/{year}/{version}/adopt 校验草稿状态、基础采用版本和 expected_adopted_version。冲突需基于当前采用版另存修订，不能覆盖新采用版。
- 草稿不推进 data_revision、不进入正式预算项目目录、不让既有快照过期。采用推进修订，旧计划和采用事件保留。
- 已绑定实际的项目不能直接把 consumption 改为 payment 或改变执行政策；需新项目及关系核对。删除项目不会删除实际消费，已知金额继续计入未分配占用，采用前显示影响条数。

R07 的明确融资事项及部分付款分配尚未开放；新增普通 repayment→payment 绑定继续拒绝。

## 2. 分类规则与批量人工修改

classification_rules 保存不可变定义及版本、draft/enabled/disabled 状态，rule_previews 冻结影响与读集。rule_revision 只在启用/停用时改变；草稿不改变当前处理。

规则仅支持明确字段的文字包含匹配，不执行用户表达式：description、merchant、product；任意/全部关键词，最多 5 个，每个不超过 200 字。同级可用 0–1000 优先级；明确商品优先于商户，商户优先于摘要。同级命中而科目或预算判断不同，保留待核。

启用需当前影响预览和 expected_rule_revision。启用用于以后导入；已有记录通过另一次当前预览显式应用，最多所列 200 笔。预览展示全量命中数，限制不是把未展示数据计为已处理。人工已分类的字段不被规则覆盖；历史解释不自动套新规则。

规则只为已确认的原生未分类消费补费用科目和空预算关联；预算关联必须属于发生年度采用计划、为合法消费口径。金额、日期、性质及账户不属于规则写权限。导入事务先保存原始解释，再以 actor=rule 保存分类版本；不会新增第二笔经济业务。原件身份使用原始解析内容，重导不因已分类而冲突。

预览依赖包含财务修订、全部来源证据摘要、启用规则版本和采用预算指针。仅补充商品证据而不推进财务修订也使旧预览失效。已启用规则冲突时，AI 上下文不授予可写字段，结构化分类提交硬拒绝；模型只能转人工。

人工批量入口支持 1–200 笔正费用消费，参数为 expected_versions、category_code/budget_line_id 和修改依据。所有目标及关联退款在同一事务中验证，任一版本冲突整批退回；actor=human、原始字段、历史及已有撤销机制保留。退款和未知性质通过单笔流程核对。

## 3. 确定性分析

GET /api/v1/analysis 使用 start_month/end_month 选择连续 1–12 个自然月。收入、费用和到账报销使用同一窗口；报销按证实到账日期，家庭赞助独立保留，不计入 R。所有金额为整数分字符串，服务计算，不依赖模型或页面分页。

period 模式按每月实际到账报销抵两侧；budget_comparison 模式将同窗累计 R 精确分配到 m 个月（余分固定分配，合计仍等于 R）。两种模式的窗口总额均满足 I*=I−R、E*=E−R、I*−E*=I−E；月均分母一致。原垫付可以不在本窗，不要求逐笔匹配或按酒店类别摊分。

窗口未结束、缺覆盖、未解释性质或纳入范围的无日期记录存在时，标 partial；未明确 estimate=true 不给年化。R>E 保留负调整并提示跨期或覆盖问题，不截零、不直接年化负费用。不生成或采用未来预算。

生活占用另需声明 living_scope：

- undeclared：生活标准化待核，消费标准化继续可用。
- observed_income：来源明确为含报销的实际已知收入；窗口各月均有采用预算且既有付款互斥可解释时，取 A_gross=同窗已知收入、U_gross=已知生活占用、R_scope=同窗到账报销，两侧各抵一次。缺覆盖仍显示 partial，不按项目摊分。
- net_salary_plan：明确来源为已排除报销的计划工资，不对该来源再减 R；不把实际收入误当未来资金计划。

输出包括原始及标准化总额/月均、逐月桥接、按主科目/明确商户或原始摘要的汇总、生活用途计划与已知占用、大额费用、退款和明细引用。大额按毛额或窗口净额筛选，退款独立保留发生期，不把还款列入消费榜。已知日常占用超过计划可提示已知超额；不足以证明支出不合理或已节省。

## 4. 快照与依据

analysis_snapshots 冻结参数、指标、自然月分母、规则/维度/覆盖/采用预算/计算定义/政策版本、来源摘要、交易 ID 与版本。保存时可提交 expected_dependencies，屏幕依据已变则要求更新分析。保存快照不推进财务修订。

金额或分类、来源证据、覆盖、计算定义、规则或所选采用预算变化使旧结果 stale，原值不重写；无关预算草稿不使其过期。页面打开旧结果时明确表示保存时值，交易抽屉打开当前解释及修改历史。

本轮不保存 AI 因果解释或节省建议；那属于 R06。真实账本的模型写入仍未启用。

## 5. 运行与验收

开发构建使用独立目录：npm --prefix web run build -- --outDir ../work/r03-web-dist-current --emptyOutDir。临时服务可指定 --web-dir 或 FINANCE_WEB_DIST，避免开发构建覆盖在线界面。

新合成接口与浏览器覆盖：草稿不影响采用版/目录/快照；过期采用拒绝和幂等回执；规则启用不静默改旧账；显式应用/冲突/人工优先；批量修改原子性和历史退款撤销；同窗迟到报销、平滑、家庭赞助排除、负调整；501 笔全量合计；覆盖/定义/来源变化失效；生活来源不含报销时防止二次扣减。

发布前通过 schema 3→4 真实影子库增量迁移、六类事实/来源表保持、完整备份独立恢复，以及 Excel 基线对照。具体测试数量和正式切换证据以开发记录为准。后续仍有 R02 权限/语义门槛、R04 扩来源及对账、R06 事件/AI 解释、R07 现金及融资计划、R08 导出、R09 投资和 R10 运行维护等。
