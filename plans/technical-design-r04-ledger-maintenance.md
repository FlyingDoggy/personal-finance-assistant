# R04 第一段：账本补录、原件和余额核对

状态：2026-10-30，开发合同；验收结果另记实施记录。沿用已采用预算、现有交易版本和确定性报表，不重新迁入真实交易。

## 本段交付

1. 交易页手工补录：填账户、业务性质、金额方向、日期、科目、用途和依据，先检查统计影响及同账户同额同日候选，再明确保存。手工记录没有伪造的银行原件；来源是可追溯的人工初始版本。过期预览拒绝、相同请求重试只创建一笔。近似候选不自动合并。
2. 交易详情下载归档原件：只按数据库登记的 SHA-256 取文件，校验长度和哈希，使用附件下载，不执行上传文件内容。原始行继续在详情中展示。文件缺失/损坏明确返回错误，不提供任意本机路径读取。
3. 余额核对工作台：逐账户保存某日终的银行余额观察，按同日、同币种和同余额定义与账本比较。现金是账户余额，信用是净欠款（负数为溢缴款），可用额度不能作为净欠款。更正同日观察追加新版本，原观察和依据保留。
4. 明确修订账户起点：现有账户支持填写/更正有证据的某日初余额，保留账户版本及修订理由。它是账户计量起点，不是收入或补差交易，也不由银行观察自动推导。修改会推进财务修订并重算余额；不改原始流水、费用或采用预算。
5. 跨历史/原生退款：同账户、同币种、已确认正费用消费可关联新退款；校验时间、累计金额、统计范围、后续修改/撤销。退款期抵费用，现金按收付日，预算按现有明确关联规则释放。跨年占用、跨账户/多对多分配仍待后续，不猜测。

## 数据与命令

schema 4→5 为增量迁移，先取得 SQLite 一致性副本。新增 `balance_observations`（账户/日唯一版本）、`account_opening_events`（前后值、账户版本、理由）、`transaction_edit_members`（人工成组修改对应的具体版本）。原有账户历史沿用 `account_versions`，不伪造迁移前历史。

- `POST /transactions/manual/preview`：只读规范化和预览；返回财务修订、候选、确认后的收入/费用/现金作用与待核原因。
- `POST /transactions`：人工补录，须带预览的 `expected_data_revision`；相同账户、同日、同额候选需另行确认，依据必填。金额使用规范分字符串；不接受 historical、任意派生作用或自造来源编号。审计 action 为 `manual_create`、actor 为 human。
- `GET /artifacts/{sha}/download`：仅浏览器账本身份；原件仍受服务现有本机权限约束，受限机器接口不开放此路径。
- `GET /reconciliation?as_of=YYYY-MM-DD&account_id=…`：最新有效观察、比较日期、起点、账本/流水推演/外部余额、差异、覆盖及未解释事项；可下钻差异期间和待核记录。
- `GET/POST /balance-observations`：列表及带同日 `expected_version` 的追加；变动只推进独立观察修订，不写账、不宣称覆盖完整。
- `POST /accounts/{id}/opening`：`expected_version`、起点金额/日、依据、理由；先幂等回执，再校验版本。`GET /accounts/{id}/opening-history` 返回追加历史。

余额观察使用日终，账户起点使用日初。观察早于查询截止时，只比较观察当日账本，不拿后续流水与旧观察硬对。未知起点时绝对差异为未知；有前后两份观察可另外比较区间变动，仍不能称绝对余额已对账。银行差额 = 银行观察 − 同口径流水推演；待解释变动单列，即使差额零也不能宣称账务完成。

完整性和数值勾稽分开：只有起点已知、窗口覆盖声明有效且所有账户变动已解释、无未定位日期、银行与账面一致时，才标该账户/观察日期核对一致。缺声明时最多说“金额一致，资料待核”。新流水/金额/日期变化使对应覆盖需复核并即时重算，不写自动平衡分录。信用账户消费/退款按确认日影响负债，其他账户变动按收付日；复用同一日期函数，避免两个页面口径分叉。

人工成组修改将每个成员及生成版本写入关系表。撤销必须仍位于该组生成的最新版本，后续子退款或人工修改不得被旧组覆盖。旧历史组仍兼容；新原生交易不新增模型可伪造的派生字段。

## 验收与切换

合成测试检查补录/重复候选/重试/过期预览、归档缺失/损坏/路径与认证、观察更正/并发/未知起点/溢缴款/旧观察日期、起点修订不制造收支、完整覆盖和零差额仍有未知业务、补录后差异与报表同步、退款跨模型/超限/类别传播/重启撤销/后续关系阻止撤销。浏览器覆盖桌面与390px，确认没有整页溢出或运行错误。

正式切换先完整备份并恢复演练，影子库验证 schema 4→5；账户/交易/历史/预算/来源行/原件六类原表内容保持，真实 Excel 逐项核对无差异。新功能验收只写临时合成库，不替用户确认真实余额或补录演示交易。

本段不宣称 R04 全部完成：其余原生格式、重复业务合并/拆分、跨日/多对多互转还款、管理范围生效修订仍另行实施。资料覆盖声明与余额核对结果分别保留。
